# SafePath AI — Render & Neon Cloud Deployment Guide

This guide details the production deployment of the SafePath AI backend on **Render Free Web Service** connected to **Neon Serverless PostgreSQL**, and building the standalone **Android Release APK** configured to communicate with the public Render HTTPS URL.

---

## 1. Cloud Architecture Overview

```
 [ Android Client ] ──────── HTTPS ────────▶ [ Render Web Service ]
 (Standalone APK)                             (FastAPI + Uvicorn)
                                                      │
                                                      │ (Internal SSL Pooler)
                                                      ▼
                                            [ Neon PostgreSQL ]
                                           (Serverless Database)
```

| Component | Provider / Platform | Specs & Tier | Responsibility |
| :--- | :--- | :--- | :--- |
| **Backend API** | Render | Free Web Service (0.1 CPU, 512 MB RAM) | FastAPI REST API, JWT auth, ML inference, SOS dispatch |
| **Database** | Neon | Free Serverless Postgres (0.5 GB storage, autoscaling compute) | Persistent relational storage (`users`, `contacts`, `sos_events`, `journeys`) |
| **ML Risk Engine** | Embedded in Backend | Calibrated Gradient Boosting (`area_risk_model.joblib`) | Pre-trained spatial risk scoring (~167 MB active memory) with deterministic fallback |
| **Mobile Client** | Android (Java) | Native Android SDK 34 | Offline-first encrypted Room DB, on-device keyword detection, cloud sync |

## 2. Deploying on Render

You can deploy using either **Option A (Render Blueprint)** or **Option B (Manual Web Service)**.

### Option A: 1-Click Render Blueprint (Recommended)

1. Log in to your [Render Dashboard](https://dashboard.render.com/).
2. Click **New +** (top right) and select **Blueprint**.
3. Connect your GitHub account and select repository `ISH2-u/SafePath`.
4. Select the deployment branch: `feature/render-neon-deployment` (or `develop` after PR merge).
5. Render detects `render.yaml` automatically:
   - **Service Name**: `safepath-backend`
   - **Runtime**: Docker (`./backend/Dockerfile`)
   - **Plan**: Free
   - **Health Check Path**: `/health`
6. In the environment variables prompt:
   - `DATABASE_URL`: Paste your **Neon PostgreSQL connection string** (see Section 3).
   - `SECRET_KEY`: Automatically generated by Render (or paste your own 64-char hex key).
7. Click **Apply**. Render will build the Docker image, run database migrations, and boot Uvicorn.

---

### Option B: Manual Web Service Creation

If you prefer configuring the Web Service manually:

1. In the Render Dashboard, click **New +** ➔ **Web Service**.
2. Connect repository `ISH2-u/SafePath` and select branch `feature/render-neon-deployment`.
3. Configure the following fields:
   - **Name**: `safepath-backend` (or your preferred name)
   - **Region**: Oregon (or Ohio / closest to your location)
   - **Branch**: `feature/render-neon-deployment` (or `develop`)
   - **Root Directory**: Leave blank (uses repository root)
   - **Runtime**: **Docker**
   - **Dockerfile Path**: `./backend/Dockerfile`
   - **Docker Context**: `./backend`
   - **Instance Type**: **Free**
4. Expand **Advanced** and set:
   - **Health Check Path**: `/health`
   - **Auto-Deploy**: Yes
5. Under **Environment Variables**, add:
   | Key | Value | Description |
   | :--- | :--- | :--- |
   | `DATABASE_URL` | `postgresql://...` | Connection string copied from your Neon project dashboard |
   | `SECRET_KEY` | *(Generate via `openssl rand -hex 32`)* | JWT signing secret key |
   | `ENVIRONMENT` | `production` | Production environment tag |
   | `DEBUG` | `false` | Disables debug mode and verbose stack traces |
   | `ALLOWED_ORIGINS` | `*` | Permits requests from mobile apps |
   | `WEB_CONCURRENCY` | `1` | Enforces 1 Uvicorn worker to preserve 512 MB memory limit |
6. Click **Create Web Service**.

## 3. Connecting Neon PostgreSQL

1. Open your [Neon Console](https://console.neon.tech/).
2. Select your project.
3. On the project **Dashboard**, locate the **Connection Details** widget.
4. Select:
   - **Role**: `neondb_owner` (or your database user)
   - **Database**: `neondb`
   - **Connection Type**: **Pooled connection** (recommended for serverless) or **Direct connection**
5. Copy the connection string. It will look like:
   ```text
   postgresql://[user]:[password]@[endpoint]-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
6. Paste this value into Render's `DATABASE_URL` environment variable field.

> [!NOTE]
> SafePath automatically normalizes `postgres://` to `postgresql://` and configures connection pooling (`pool_recycle=300`, `pool_pre_ping=True`) so serverless compute pause/resume transitions never drop queries.

## 4. Automated Startup & Database Migrations

When Render boots the backend container:
1. `entrypoint.sh` executes as non-root user `safepath`.
2. It polls the Neon database connection for up to 60 seconds with exponential retry.
3. It runs `alembic upgrade head` against Neon, creating/verifying all production tables:
   - `users`
   - `emergency_contacts`
   - `journeys`
   - `sos_events`
4. It boots Uvicorn bound to `0.0.0.0:$PORT` with 1 worker process.
5. Render verifies the service is ready via HTTP GET `/health`.

## 5. Building the Standalone Release APK

Once your Render service is live at `https://<your-service-name>.onrender.com`:

```bash
cd android-app

# Build the release APK injecting your Render HTTPS endpoint
./gradlew clean :app:assembleRelease \
  -PPROD_API_BASE_URL="https://<your-service-name>.onrender.com/api/v1/"
```

### APK Output Location
```text
~/.android_builds/SafePathAI/app/outputs/apk/release/app-release.apk
```

### Install onto your Android phone:
```bash
adb install -r ~/.android_builds/SafePathAI/app/outputs/apk/release/app-release.apk
```
*Or transfer `app-release.apk` to your phone via Google Drive, Telegram, or USB file transfer and install directly.*

## 6. Cold-Start & Free-Tier Optimization Details

- **Render Free Inactivity Spin-Down**: Render spins down free web services after 15 minutes of inactivity. When a user opens the app after an idle period, Render takes approximately 30–45 seconds to spin up.
- **Android Cold-Start Resilience**: OkHttpClient in `RetrofitClient.java` has been configured with **60-second connect, read, and write timeouts**. The Android application will wait gracefully for the Render container to wake up without throwing socket timeout errors.
- **Memory Footprint**: Total memory usage of the running backend (FastAPI + SQLAlchemy + Scikit-Learn Area Risk model) is **~167 MB**, which leaves ample headroom under Render's **512 MB** ceiling.
